# Процесс: роли, типы агентов, уровни интеллекта, диспетчеризация, гейты

Пакет исполняется агентами под управлением архитектора; владелец принимает результат и делает
то, что может только он. Закон токен-дисциплины перенесён из Ties Break (29.09.2026) и Onsight
(04.10.2026) без смягчений: измеренные там числа – причина правил.

## §1 · Роли

| Роль | Что делает | Чего не делает |
|---|---|---|
| **Архитектор** | пишет и правит спеки, составляет таблицу диспетчеризации волны, запускает агентов по одному, читает отчёты, гоняет гейты, принимает этап по разделу «Гейт архитектора», пишет карточку волны | не пишет объёмный код сам (точечные правки допустимы), не меняет вординг игры |
| **Builder** | реализует ровно один шаг спеки: код + тесты + коммит в ветку этапа + отчёт | не расширяет объём, не трогает `DesktopDrift`, не запускает тяжёлые гейты внутри себя |
| **Importer** (ассет-билдер) | скрипты пайплайна: экспорт данных из JS, импортёры SVG/glTF, Blender-скрипты, подгонка моделей, палитризация, credits | не рисует «от руки», не меняет данные-источники |
| **Reviewer** | отдельное критическое ревью этапа в свежей сессии: дифф против спеки, тесты против ожиданий, паритет | не чинит сам (находки – архитектору) |
| **Explorer** (разведчик) | read-only поиск по коду/докам/веб, возвращает выжимку с путями и строками | ничего не меняет |
| **Gate-runner** | тонкий агент: запускает один гейт (`scripts/*.sh`) в фоне, собирает вердикт в файл | не правит код |
| **Promoter** | тексты листинга, скриншоты по сценарию, анкеты стора (по образцу `DesktopDrift/docs/promo/PROMOTER_AGENT.md`) | не трогает код |
| **Владелец** | установки, модели, аккаунты, keystore, телефоны, подпись фила, PR/мерж, тестеры | – |

## §2 · Типы агентов (механизм запуска)

| Тип | Когда | Как |
|---|---|---|
| **Сессия архитектора** | каждая волна начинается в свежей сессии (Fable 5.1, этот класс модели) | читает `CURRENT.md` + одну спеку + карточку прошлой волны |
| **Субагент `general-purpose`** | Builder / Importer / Gate-runner / Reviewer на один шаг | бриф = самодостаточная выдержка (§4), бюджет ходов как стоп-условие |
| **Субагент `Explore`** | read-only разведка, можно параллельно нескольких | только чтение; результат – пути и строки |
| **Субагент `Plan`** | редко: развилка внутри шага, где нужен план, а не код | возвращает план архитектору, не исполняет |
| **Отдельная сессия Builder** | длинный этап с одним исполнителем (например, SPEC-06 экраны), когда бриф > 10k | та же дисциплина: шаги по очереди, отчёт после каждого |

Параллельно – только read-only (`Explore`). Код пишут строго по одному.

## §3 · Уровни интеллекта (модель × усилие)

Уровень выбирается на ШАГ, не на этап. В спеках каждый шаг помечен ⟨роль · тип · модель ·
усилие · бюджет ходов⟩.

| Уровень | Модель | Усилие | Для чего | Чего избегать |
|---|---|---|---|---|
| **L1 механика** | Haiku 5.5 (`haiku`) | low–medium | разбор логов, пакетная обработка ассетов по готовому скрипту, перенос таблиц по шаблону, credits, переименования, сверка списков | любое решение; всё, где есть «а как лучше» |
| **L2 ремесло** | Sonnet 5.5 (`sonnet`) | medium–high | **умолчание для кода по точной спеке**: перенос модулей 1:1, NUnit-тесты по JS-образцу, импортёры, экраны UI по дизайн-спеке, скрипты CLI, Blender-скрипты | неопределённые швы дизайна, перф-отладка на устройстве |
| **L3 суждение** | Opus 5.5 (`opus`) | high–xhigh | feel-критичный код (камера C2/C3, следы под мобильный бюджет), отладка детерминизма и платформенных капризов, ревью этапа, развилки с измерением | массовая выработка кода (дорого, не быстрее Sonnet на ясной спеке) |
| **L4 архитектор** | Fable 5.1 (`fable`) | max | спеки, диспетчеризация, гейты, решения, разбор инцидентов | писать код этапа; читать логи целиком |

Правило выбора: если шаг описан так, что ошибку поймает тест или сравнение с JS – L2. Если
ошибку поймает только глаз владельца или устройство – L3. Если шаг – «сделай по списку» – L1.

Бюджет ходов (ход = один вызов инструмента): L1 ≤ 25, L2 ≤ 60, L3 ≤ 80. Это **стоп-условие в
брифе**: достигнув бюджета, агент коммитит зелёное, пишет что осталось, останавливается;
остаток – новому тонкому агенту. Измерено в Ties Break: задача на ~40 ходов без стопа ушла в
112 вызовов и 372k токенов.

## §4 · Бриф агента (обязательная форма)

1. **Цель** – одно предложение, наблюдаемый результат.
2. **Объём** – точный список артефактов; всё, чего нет в списке, вне объёма.
3. **Выдержка спеки** – ≤ 20 строк нужного раздела ЦИТАТОЙ, не ссылкой; файлы-источники с
   диапазонами строк (`sed -n '23,66p' …/js/physics.js`), не «прочитай файл».
4. **Acceptance** – команда и ожидаемый вывод (`scripts/test.sh` → `TEST_EXIT=0`, число тестов).
5. **Бюджет** – модель, усилие, ≤ N ходов, стоп-условие.
6. **Отчёт** – ≤ 30 строк: что изменено (файлы), как проверено (команда + код выхода), что
   осталось, сколько ходов ушло.
7. **Блок дисциплины** (дословно в каждом брифе):
   > - Пакетируй пробы: `cmd1 && cmd2 && cmd3` в одном вызове.
   > - Читай один раз: один `sed -n` по нужным диапазонам, один `grep -n` со всеми паттернами.
   > - Никакой разведки «на всякий случай»: бриф называет файлы; шире – только с причиной в отчёте.
   > - Режь вывод у источника: `2>&1 | tail -40`, `--nologo -v q`, `| grep -c`.
   > - Ветка: `git branch --show-current` перед коммитом; в `main` никогда.

## §5 · Диспетчеризация волны (обязанности архитектора)

1. Таблица шагов волны: шаг · роль · тип · модель · усилие · бюджет · вход · выход · acceptance.
   Берётся из спеки, уточняется по карточке прошлой волны. Без таблицы агенты не запускаются.
2. Один агент – один шаг с определённым выходом. «И ещё» в брифе = два агента.
3. Код пишут последовательно: шаг лёг, отчёт прочитан, следующий стартует.
4. Тяжёлые гейты (`unity-tests.sh`, `build.sh`, трасса паритета на полном следе) – в сессии
   архитектора или в тонком Gate-runner, никогда внутри толстого Builder.
5. В агента, который уже отработал, сообщений не слать: продолжение – новый тонкий агент с
   новой выдержкой.
6. Агент умирает сразу после отчёта.
7. Владелец получает: вердикт гейта, цифры, что требуется от него. Жаргон – в карточку волны.

## §6 · Гейт этапа и граница волны

1. Builder/Importer работают в ветке `feat/spec-NN-<slug>` по одному шагу за раз.
2. По завершении этапа – **свежая сессия архитектора** проходит раздел «Гейт архитектора»
   спеки на живом коде: гоняет скрипты, смотрит цифры, при необходимости вызывает Reviewer (L3).
3. Фил-гейты (камера, управление, машина, звук) подписывает владелец на телефоне; агент
   готовит сборку и чек-лист, не заменяет глаз.
4. Гейт пройден → статус ⬛ в `CURRENT.md`, PR, мерж владельцем. Не пройден → находки в
   спеку («Находки гейта»), итерация новым агентом.
5. Волна закрывается карточкой `docs/handoff/<волна>.md` (шаблон в `handoff/README.md`);
   следующая волна – новая сессия, первое чтение – карточка и `CURRENT.md`.

## §7 · Определение «сделано» для шага

- код по-английски, в ветке этапа, минимальный дифф, без TODO без номера решения;
- `scripts/test.sh` зелёный; для Unity-слоя – `scripts/compile.sh` без ошибок и
  `scripts/unity-tests.sh` зелёный; новая чистая логика с тестом в том же коммите;
- данные не перепечатаны руками (экспорт из JS + импортёр);
- отчёт по §4 п.6; ходы в бюджете (превышение – отдельной строкой с причиной).

## §8 · Бюджет пакета (ориентир)

| Этап | Шагов | Агентов (ориентир) | Ходов (сумма бюджетов) |
|---|---|---|---|
| SPEC-00 | 12 | 12 | ~455 |
| SPEC-01 | 9 | 9 | ~500 |
| SPEC-02 | 12 | 12 | ~670 |
| SPEC-03 | 9 | 9 | ~440 |
| SPEC-04 | 9 | 9 (+1 на каждую машину 3–8) | ~460 |
| SPEC-05 | 9 | 9 | ~385 |
| SPEC-06 | 12 | 12 | ~580 |
| SPEC-07 | 9 | 9 | ~365 |
| SPEC-08 | 4 | 4 | ~160 |
| SPEC-09 | 9 | 7 + владелец | ~320 |
| SPEC-10 | 6 | 4 + владелец | ~140 |
| **Итого** | **100** | **~96 + владелец** | **~4 450** |

Это верхняя граница: по измерениям владельца тонкий агент на 60 ходов стоит порядка $3, толстый
на 200 – порядка $30; дисциплина §3–§5 держит пакет в первом режиме.
