0. **Действие, не вопрос:** один раз открыть Unity 6000.3.27f1 в GUI (Hub → проект `DesktopDrift3d/unity`, либо `unity open unity` из обычного терминала), принять Unity Software Terms, закрыть. · Пока не сделано, `unity open unity` висит в модальном окне (100% CPU, лог обрывается после лицензии), `unity status` GUI-редактор не видит. · После этого заработает GUI-путь (`unity open`/`close`, снимок `source=screen`); все headless-пути работают уже сейчас.
1. Android package id `com.letulip.desktopdrift`, companyName `letulip`, productName «Desktop Drift» – оставить? · Плейсхолдеры, по одной константе в `unity/Assets/Editor/Setup/ProjectSetup.cs`. · Другие значения – правка трёх констант и один прогон `unity run unity -- -executeMethod DesktopDrift.Editor.ProjectSetup.Apply`; id нужно зафиксировать до первой загрузки в Play Console (SPEC-09).

## Ответы владельца (28.10.2026) и решения (D-19, D-20)

0. «принято» → Software Terms приняты. Проверка GUI-пути архитектором – `docs/handoff/wave-1.md` «Гейты».
1. «оставить» → плейсхолдеры остаются до SPEC-09.
2. «можно» → разрешение записано; не применяем решением архитектора: проектный `.mcp.json` покрывает все сессии Claude Code в репозитории и его worktree (`$PWD/unity`), глобальная запись привязана к пути одного проекта и поднимала бы сервер в каждой сессии любого проекта, Claude Desktop получил бы 166 схем инструментов в каждый чат. Команды на случай нужды – `docs/tooling/unity-mcp.md`.
3. «чем-то грозит? есть подводные камни?» → `unity skill install claude-code` пишет `~/.claude/skills/unity-cli` (глобально, во все проекты мака; текст общий от Unity и в одном месте расходится с нашим контуром – `unity status` batch-редактор видит; привязан к версии CLI, после обновления переустанавливать); `unity setup claude` = `claude plugin marketplace add Unity-Technologies/unity-agent-plugin --scope user` + `claude plugin install unity@unity-agent-plugin --scope user` – бета-плагин в user-scope: грузится в каждой сессии Claude Code на маке (Onsight, Ties Break…), обновляется по своему графику, меняет `~/.claude`. Решение: не ставить; тот же текст навыка уже лежит в `docs/tooling/unity-cli-skill.md`; пересмотр на стабильном 1.0.
4. «это построит версию для macOS или что?» → да: `DesktopDrift.app` для macOS (StandaloneOSX, Mono, universal x86_64+arm64) – играть за столом без телефона на SPEC-02/03 и снимать настольные кадры; не релиз (D-02). Проверено 28.10: 65 с, 114 МБ, exit 0. Оставлен как проверочная цель, пометка долга снята.
5. «наверное подходит» → принято; подпись и AAB – SPEC-09.
6. «что это дает? чем чревато?» → флаг снимает защиту CLI «дерево с незакоммиченными правками – сборку не делаю»: даёт сборку текущего рабочего состояния до коммита (так работает гейт контура и так Builder проверяет шаг). Чревато сборкой, которую не привязать к коммиту. Снято 28.10: `artifacts/build/report.md` печатает коммит и число незакоммиченных файлов, CLI сам кладёт `*.provenance.json` рядом с артефактом (revision, dirty, версии пакетов). Релиз SPEC-09 – без флага, из чистого дерева.
7. «а почему не хочешь обновлять?» → не «никогда», а «не внутри волны и не автоматически»: беты меняют флаги (три расхождения со спекой уже на beta.13), `unity command/status/mcp` зависят от версии Pipeline-пакета в проекте (`unity pipeline upgrade` – отдельный шаг), после обновления нужен полный прогон шести скриптов и MCP (~10 мин машинного времени) и правка `docs/tooling`. beta.14 вышла 28.10: добавляет `unity terms accept/status` (ровно наш вопрос №0) и коды `OPEN/STATUS_BLOCKED_BY_DIALOG_SOFTWARE_TERMS`. Решение: обновляем на границе волн; первое окно – шаг 0 Волны 2 (SPEC-01), не под открытым PR Волны 1.
8. «портретная, как в оригинале, но надо посмотреть на PoC» → D-19: портрет – гипотеза (2D `manifest.json`: `"orientation": "portrait"`), решение на гейте SPEC-02; до него автоповорот Portrait + оба Landscape (`ProjectSetup`, применено 28.10).
