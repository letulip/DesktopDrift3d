# DesktopDrift3d – пакет архитектора для порта Desktop Drift на Unity (low-poly 3D)

> Статус пакета: **спеки написаны 27.10.2026, работы не начаты.** Единственный источник
> текущего состояния – [docs/CURRENT.md](docs/CURRENT.md). Здесь – карта, порядок и правила.

Исходная игра: `/Users/letulip/Projects/Claude/DesktopDrift` – живая 2D-игра (Vanilla JS +
Canvas, GitHub Pages, порталы). Для этого проекта она **источник истины по поведению и
данным и только для чтения**: формулы, таблицы, тесты и SVG оттуда переносятся, сам репозиторий
не трогается.

Цель пакета: 3D-издание Desktop Drift на Unity 6 с low-poly графикой, **1.0 = native-first**
(AAB для Google Play, iOS вторым, веб-сборка Unity опционально после 1.0), платное, без
рекламы, с паритетом управления и контента к 2D-версии (объём 1.0 = MVP, решения D-13, D-15…D-17).

Волны (по закону токен-дисциплины: один этап = одна ветка, агенты последовательно, гейт
архитектора отдельной сессией, граница волны = карточка в `docs/handoff/`):

1. **Волна 0 – владелец**, параллельно с частью A SPEC-00: установить Unity, принести две модели,
   проверить аккаунт Google Play (см. «Задачи владельца»).
2. **Волна 1** – SPEC-00 → SPEC-01. Гейт: контур работает из CLI, трасса паритета сходится.
3. **Волна 2** – SPEC-02. Гейт: владелец проезжает Time Attack на серой трассе на телефоне,
   подписывает камеру C2 и управление.
4. **Волна 3** – SPEC-03 → SPEC-04. Гейт: 12 инстансов трасс играются, две машины с косметикой.
5. **Волна 4** – SPEC-05 → SPEC-08. Гейт: 6 трасс одеты, 60 fps на контрольном телефоне, звук.
6. **Волна 5** – SPEC-07 → SPEC-06. Гейт: каждый экран 2D-игры имеет 3D-двойника, сейв
   переживает перезапуск и покупки.
7. **Волна 6** – SPEC-09 → SPEC-10. Гейт: AAB проходит проверки Play, закрытый тест идёт, листинг готов.

Порядок внутри волны – строго последовательный (03 перед 04, 07 перед 06): так сказано в
[02-process.md](docs/02-process.md) §3.

## Задачи владельца (никто другой их сделать не может)

1. Установить через Unity Hub **Unity 6.3 LTS (6000.3.x)** с модулями Android Build Support +
   OpenJDK + Android SDK & NDK Tools (~15 ГБ; на 27.10 свободно 72 ГБ) – пошагово в
   [docs/tooling/unity-install.md](docs/tooling/unity-install.md). Без этого SPEC-00 часть B и всё
   после SPEC-01 стоят.
2. Принести **две первые модели машин** (Bismark и Panda, как в начале проекта) в формате из
   чек-листа SPEC-04 §2 (Blender-исходник + glTF).
3. Контрольные **Android-телефоны** с режимом разработчика: Poco X6 (контрольный) и Motorola G8 Plus
   (слабый), по D-16.
4. Проверить в Play Console дату создания личного аккаунта (SPEC-09 §2): до 13.11.2023 –
   гейта закрытого теста нет; позже – нужны 12 тестеров на 14 дней, план набора в SPEC-09 §6.
5. Подписывать фил: камера и управление (гейт SPEC-02), каждая машина (гейт SPEC-04).
6. Создать keystore для подписи AAB по инструкции SPEC-09 §4 (пароль остаётся у владельца).
7. Позже: Apple Developer Program для iOS (SPEC-09 приложение A).

## Правила проекта (кратко; полностью в CLAUDE.md и 02-process.md)

- В `main` никто не пушит и не коммитит; работа в ветке этапа `feat/spec-NN-…`; PR открывает и
  мержит владелец.
- Код, комментарии и строки интерфейса – по-английски (как в DesktopDrift). Документы пакета –
  по-русски.
- Числа и формулы из 2D-игры переносятся 1:1; изменение поведения – только отдельным решением
  в `01-decisions.md`.
- Агенты толстыми не бывают: бюджет ходов в брифе – стоп-условие.
